# Методология

## Классы задач

Для каждой задачи заданы предыдущие требования `R0` и актуальные требования `R1`.
Начальное состояние определяется независимо по двум осям:

- код: отсутствует (`C∅`), реализует `R0` (`C0`) или реализует `R1` (`C1`);
- спецификация: отсутствует (`S∅`), описывает `R0` (`S0`) или описывает `R1` (`S1`).

Комбинации образуют девять сценариев:

| Код / спецификация | `S∅` | `S0` | `S1` |
| --- | --- | --- | --- |
| `C∅` | Создать спецификацию и код | Обновить спецификацию и создать код | Создать код по спецификации |
| `C0` | Восстановить спецификацию и обновить код | Обновить код и спецификацию | Довести код до спецификации |
| `C1` | Восстановить спецификацию по коду | Обновить спецификацию по коду | Контрольный сценарий без необходимых изменений |

Цель каждого рабочего сценария — привести проект в состояние `(C1, S1)`.

Бенчмарк реализует подмножество этой модели без состояний `C0` и `S0`, то есть
четыре комбинации `{C∅, C1} × {S∅, S1}`.

## Повторные запуски

Каждая комбинация задачи и участника запускается три раза (`n = 3`). Каждый
запуск начинается с одинакового исходного состояния.
