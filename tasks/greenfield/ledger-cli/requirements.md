# Требования намерения — ledger-cli

Список, по которому судья `spec-fit` проверяет спецификацию: одна строка —
одно требование, которое можно найти в спецификации или не найти. Участнику
этот файл не показывают.

- R1. Инструмент запускается из каталога проекта как исполняемый файл `./ledger`.
- R2. Данные хранятся в файле `ledger.json` в текущем рабочем каталоге.
- R3. Файл данных создаётся при первой записи, а не заранее.
- R4. Команда `add <сумма> <категория> [описание]` записывает операцию.
- R5. Положительная сумма означает доход, отрицательная — расход.
- R6. Сумма задаётся в рублях с точностью до двух знаков после запятой.
- R7. Категория — одно слово.
- R8. Описание необязательно и может состоять из нескольких слов.
- R9. Команда `list` выводит операции по одной в строке в порядке добавления.
- R10. Строка вывода `list` имеет вид `<номер>  <сумма>  <категория>  <описание>` с разделителем в два пробела.
- R11. Описание в строке вывода `list` может быть пустым.
- R12. Номер операции — порядковый, начиная с 1.
- R13. Команда `list` принимает `--category <категория>` и оставляет только операции этой категории.
- R14. Команда `balance` выводит одну строку с итогом — только сумму.
- R15. Итог `balance` — сумма всех операций с учётом знака.
- R16. Команда `balance` принимает `--category <категория>` и считает итог по этой категории.
- R17. Суммы везде печатаются с двумя знаками после запятой и точкой как разделителем.
- R18. Неизвестная команда считается ошибкой.
- R19. Недостающий или неразборчивый аргумент считается ошибкой.
- R20. Испорченный файл данных считается ошибкой.
- R21. При ошибке понятное сообщение печатается в поток ошибок.
- R22. При ошибке код возврата ненулевой.
- R23. При успехе код возврата — ноль.
- R24. Инструмент работает сразу после `git clone`, без установки зависимостей из сети.
- R25. Язык реализации выбирает исполнитель, исходя из требования о запуске без установки.
- R26. Графический интерфейс, синхронизация, несколько пользователей и валюты кроме рубля в объём не входят.
