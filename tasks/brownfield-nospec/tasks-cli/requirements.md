# Требования намерения — tasks-cli

Список, по которому судья `spec-fit` проверяет спецификацию. Участнику этот файл
не показывают.

Задача brownfield: намерение говорит «всё остальное — как сейчас», и этой
оговоркой делает требованием то, что уже написано в коде. Поэтому P1–P8 названы
в намерении прямо, а K1–K12 восстанавливаются по проекту. Спецификация, которая
описала только новое и промолчала о сохранении прежнего, требований K не
покрывает — и это не придирка, а ровно та работа, которую заказчик заказал
словами «те же команды, тот же вид вывода, те же коды возврата».

- P1. У задачи есть приоритет.
- P2. Приоритетов ровно три: высокий, обычный, низкий.
- P3. Задача, которой приоритет не назвали, получает обычный.
- P4. Приоритет можно указать при добавлении задачи.
- P5. Приоритет виден в выводе списка.
- P6. В списке задачи идут по убыванию приоритета: сначала высокие, потом обычные, потом низкие.
- P7. Среди задач одного приоритета сохраняется прежний порядок — тот, в каком они лежат в файле.
- P8. Список можно ограничить задачами выбранного приоритета.
- K1. Уже накопленный `tasks.json` продолжает читаться, и ни одна запись из него не теряется.
- K2. Запись, сделанная до появления приоритетов, получает приоритет по умолчанию.
- K3. Набор команд прежний: `add`, `list`, `done`, `tags`, и никаких новых.
- K4. Строка списка по-прежнему несёт номер, отметку выполнения, текст и теги.
- K5. Номер задачи — её место в файле, и ни отбор, ни новый порядок вывода его не меняют.
- K6. `done <номер>` по-прежнему отмечает выполненной задачу с этим номером.
- K7. Отборы `--done`, `--open` и `--tag` продолжают работать, в том числе вместе с новым.
- K8. Команда `tags` продолжает считать задачи по тегам.
- K9. Пустой список — не ошибка: пустой вывод и нулевой код возврата.
- K10. Код возврата прежний: ноль при успехе, ненулевой при ошибке.
- K11. Сообщения об ошибках по-прежнему идут в поток ошибок, а не в стандартный вывод.
- K12. Инструмент по-прежнему работает без установки зависимостей из сети.
- N1. Сроки, проекты, цветной вывод и правка добавленной задачи в объём не входят.
