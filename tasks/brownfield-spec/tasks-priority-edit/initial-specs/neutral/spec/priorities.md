# Приоритеты задач — спецификация

## Цель и границы

Программа `./tasks` получает ровно одно новое свойство задачи — приоритет.
Поддерживаются только добавление приоритета, его показ в списке, порядок
списка и отбор по нему. Редактирование существующей задачи, сроки, проекты,
цвета и другие возможности в эту работу не входят.

Значения в интерфейсе и файле фиксированы: `high`, `normal`, `low`.
Текстовые подписи в выводе: `high`, `normal`, `low`. Такое решение делает
значение однозначным и пригодным для сценариев командной строки.

## Требования

### PRIO-001 — модель приоритета

Каждая задача имеет приоритет одного из трёх значений: `high`, `normal` или
`low`. Новая задача без явно указанного приоритета получает `normal`.

### PRIO-002 — добавление задачи

Команда имеет вид:

```
tasks add <текст> [--tag <тег>] [--priority <high|normal|low>]
```

Опцию `--priority` можно передавать в любом месте среди слов команды и других
опций. Она требует значение. Неизвестное, пустое или отсутствующее значение
является ошибкой использования, записывается в stderr и завершает команду с
существующим ненулевым кодом. Значение приоритета не нормализуется: допустимы
только три точные строчные формы выше.

### PRIO-003 — хранение и совместимость

В JSON-представление каждой задачи входит поле `priority` со строковым
значением. Формат записи повышается до версии 2.

Файлы версии 1 и файлы без поля `version` продолжают читаться. Если у записи
нет поля `priority`, ей назначается `normal`; её текст, признак выполнения,
теги и позиция не меняются. При следующем сохранении такая запись получает
поле `priority: "normal"` и версию файла 2.

Поле `priority`, присутствующее в файле, обязано быть одной из трёх строк из
PRIO-001. Иное значение или тип делает файл испорченным по тем же правилам,
что и остальные неверные поля задачи.

### PRIO-004 — показ списка

Каждая строка `tasks list` показывает приоритет сразу после отметки состояния:

```
<номер>. [<x или пробел>] [<priority>] <текст>  <теги>
```

Номер, отметка выполнения, текст, теги и их выравнивание сохраняют прежние
правила; добавляется только поле `[priority]`. Пустой список по-прежнему не
печатает строк и завершается успешно.

### PRIO-005 — порядок списка

После всех выбранных фильтров `tasks list` упорядочивает задачи по приоритету:
сначала `high`, затем `normal`, затем `low`. Задачи с одинаковым приоритетом
сохраняют порядок файла. Напечатанный номер остаётся исходной позицией задачи
в файле, а не позицией в отсортированном выводе.

### PRIO-006 — фильтр списка

Команда поддерживает дополнительную опцию:

```
tasks list [--done|--open] [--tag <тег>] [--priority <high|normal|low>]
```

Фильтр приоритета пересекается с фильтрами состояния и тега. Ошибки значения
`--priority` следуют правилам PRIO-002. Имеющееся взаимоисключение `--done` и
`--open` остаётся без изменений.

### PRIO-007 — сохранение прежнего поведения

Команды `done` и `tags`, существующие параметры, сообщения об их ошибках и
коды завершения не меняются. `done` продолжает принимать номер позиции в
файле, независимо от нового порядка `list`. Все старые записи остаются в
исходном порядке и доступны теми же номерами.

## Принятые решения

* Повторённая опция `--priority` использует последнее указанное значение —
  так же, как уже существующая `--tag`.
* Фильтр по `normal` включает как новые задачи, так и старые записи, где поле
  приоритета отсутствовало.
* Порядок применяется также к спискам с `--done`, `--open` и/или `--tag`;
  фильтрация всегда предшествует сортировке.
